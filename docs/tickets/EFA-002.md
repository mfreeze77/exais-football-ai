# EFA-002 — Persist film records and immutable source provenance

**Status:** in_progress
**Milestone:** M1 — Working local film library and safe external adapter foundations
**Priority:** P0
**Area:** storage
**GitHub issue:** [#2](https://github.com/mfreeze77/exais-football-ai/issues/2)

## Outcome and user value

Keep every review attached to the correct original film across application restarts.

## Scope

- Create SQLite records for clips, games, players, tags, revisions, notes, playlists, jobs, and imported suggestions.
- Assign opaque IDs and retain source SHA-256, duration, media properties, original filename, and application-owned storage location.

## Non-goals

- Roster biometric identity resolution, cloud databases, or deducing a person's identity from a file hash.

## Acceptance checks

- [ ] Restarting the application preserves imported records and relationships.
- [ ] Foreign-key enforcement rejects nonexistent game, player, or clip references.
- [ ] SHA-256 and media properties cannot be changed through metadata edit routes.
- [ ] Source-relative times remain stable when a view range or title changes.
- [ ] Database files and media directories are ignored by git.

## Dependencies

- [EFA-001](EFA-001.md)

## Risks and evidence boundaries

- A source hash identifies bytes; separate clips of the same player must never be merged by identity assumptions.
- Multiple-source and multi-angle models may require later additive migrations.
