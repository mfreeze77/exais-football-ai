# EFA-041 — Qualify Windows packaging and live Kinovea workflows

**Status:** planned
**Milestone:** M4 — Desktop convenience, recovery, scale, and release confidence
**Priority:** P1
**Area:** desktop
**GitHub issue:** [#41](https://github.com/mfreeze77/exais-football-ai/issues/41)

## Outcome and user value

Use the film room and Kinovea together on a real supported Windows installation.

## Scope

- Package or document a repeatable Windows installation and configured external Kinovea path.
- Execute live single/comparison launch, saved sidecar reopening, field mapping, and Unicode/space path checks.

## Non-goals

- Emulating native acceptance through mocks, redistributing Kinovea source inside this repository, or assuming every old release behaves identically.

## Acceptance checks

- [ ] The test record names Windows, CPU architecture, Kinovea release, Python/runtime, and FFmpeg versions.
- [ ] A managed source opens in the configured Kinovea application and a saved KVA can be preserved/reopened.
- [ ] The -video2 comparison handoff is tested on the declared supported release.
- [ ] Unsupported KVA versions and unavailable executables fail clearly without changing the catalog.
- [ ] Core import/trim/export retains audio and source hash on Windows.
- [ ] Installer/launcher uninstall leaves user media and the database intact.
