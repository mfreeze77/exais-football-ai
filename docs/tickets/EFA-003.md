# EFA-003 — Import existing clips safely with duplicate detection

**Status:** implemented
**Milestone:** M1 — Working local film library and safe external adapter foundations
**Priority:** P0
**Area:** ingest
**GitHub issue:** [#3](https://github.com/mfreeze77/exais-football-ai/issues/3)

## Outcome and user value

Bring the owner's existing game clips into the library without damaging originals or multiplying identical imports.

## Scope

- Accept bounded multipart video uploads and copy successful imports into managed storage.
- Probe media, compute source hashes, create thumbnails where available, and report duplicates explicitly.

## Non-goals

- Whole-game automatic play detection, remote video download, and importing arbitrary server filesystem paths.

## Acceptance checks

- [x] A generated audio/video fixture imports with the correct duration, dimensions, audio flag, and source hash.
- [x] A second import of identical bytes returns the original clip ID and duplicate=true.
- [x] Unsupported, corrupt, oversized, and empty uploads return useful errors and leave no committed clip.
- [x] Client filenames containing traversal or shell characters cannot escape the managed workspace.
- [x] A failed probe or copy does not leave a valid-looking clip with missing source bytes.

## Dependencies

- [EFA-002](EFA-002.md)

## Risks and evidence boundaries

- Content-type and file extension alone are not proof that a video can be decoded.
- Source copying requires temporary space; failure cleanup must preserve existing clips.
