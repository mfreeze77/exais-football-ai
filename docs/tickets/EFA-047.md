# EFA-047 — Maintain dependency provenance and upstream upgrade gates

**Status:** planned
**Milestone:** M4 — Desktop convenience, recovery, scale, and release confidence
**Priority:** P1
**Area:** maintenance
**GitHub issue:** [#47](https://github.com/mfreeze77/exais-football-ai/issues/47)

## Outcome and user value

Keep integrations reproducible and avoid breaking the film library when dependencies or external projects change.

## Scope

- Record a dependency inventory, lock strategy, license notices, external model sources, and pinned adapter compatibility.
- Create an update checklist that reviews upstream changes, schema fixtures, and affected qualified workflows.

## Non-goals

- Relicensing upstream code, claiming one root license covers model weights, or copying unlicensed alternatives.

## Acceptance checks

- [ ] The repository retains Apache-2.0 for original code and documents separately governed external tools/dependencies.
- [ ] football-cv code commit, backend versions, and weight artifacts are independently identifiable.
- [ ] Updating an adapter pin requires fixture/schema regression checks and a reviewed capability change note.
- [ ] Kinovea stays external and GPL/AGPL alternatives are referenced without source ingestion.
- [ ] A release inventory distinguishes distributed dependencies from optional user-installed tools.
- [ ] The policy provides a safe rollback pin and does not auto-update analysis components at app startup.
