# EFA-012 — Provide safe external Kinovea launch and KVA preservation

**Status:** in_progress
**Milestone:** M1 — Working local film library and safe external adapter foundations
**Priority:** P0
**Area:** integrations
**GitHub issue:** [#12](https://github.com/mfreeze77/exais-football-ai/issues/12)

## Outcome and user value

Keep Kinovea available for detailed technique review while retaining its sidecar with the library clip.

## Scope

- Report configured Kinovea capability and launch only a locally configured executable on supported Windows systems.
- Validate size-bounded KVA XML without DTD/entities, preserve original bytes, and download saved sidecars.

## Non-goals

- Native Windows acceptance in this milestone, automatic working-zone/tag synchronization, or copying GPL code.

## Acceptance checks

- [ ] Unsupported platforms or missing configuration return an explicit unavailable reason.
- [ ] A mocked Windows launch uses a command array and a managed clip path; request bodies cannot select an executable.
- [ ] Malformed XML, DTD/entities, unsupported roots/schema, and oversized uploads are rejected.
- [ ] A valid sidecar is preserved byte-for-byte and retrieved only through its clip association.
- [ ] KVA import does not silently overwrite the library's tags, notes, trim, or source hash.
- [ ] Documentation distinguishes adapter tests from the later real-Windows qualification gate.
