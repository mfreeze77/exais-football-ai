# EFA-027 — Reconcile Kinovea and catalog edits without silent data loss

**Status:** planned
**Milestone:** M2 — Faster film study and deeper Kinovea interoperability
**Priority:** P1
**Area:** integrations
**GitHub issue:** [#27](https://github.com/mfreeze77/exais-football-ai/issues/27)

## Outcome and user value

Return from external technique review with a clear account of what changed on both sides.

## Scope

- Track last-imported sidecar hash and catalog revision; build a three-way comparison for supported fields.
- Apply approved changes as new catalog revisions and preserve original/updated KVA versions.

## Non-goals

- Bidirectional synchronization of unsupported fields, background sidecar overwrites, or direct changes to the user's original video.

## Acceptance checks

- [ ] Independent catalog and KVA edits to the same supported field produce an explicit conflict.
- [ ] Unchanged fields do not generate duplicate notes or revisions on repeated imports.
- [ ] Accepting a proposal records the KVA hash, reviewed changes, and prior/current clip versions.
- [ ] Rejecting a proposal leaves both catalog and sidecar bytes intact.
- [ ] Unknown KVA elements survive any documented sidecar export; otherwise export is disabled for that schema.
