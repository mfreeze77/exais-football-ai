# EFA-042 — Back up and restore a complete film library

**Status:** planned
**Milestone:** M4 — Desktop convenience, recovery, scale, and release confidence
**Priority:** P0
**Area:** recovery
**GitHub issue:** [#42](https://github.com/mfreeze77/exais-football-ai/issues/42)

## Outcome and user value

Recover the owner's clips, labels, sidecars, and review history on a replacement computer.

## Scope

- Create a consistent SQLite backup plus a versioned manifest for sources, derived files, notes, revisions, playlists, KVA, and analysis records.
- Restore into a new managed workspace with checksum verification and a dry-run report.

## Non-goals

- Automatic cloud upload, treating a database-only copy as a complete backup, or overwriting a live library without explicit reviewed intent.

## Acceptance checks

- [ ] Backup taken while the app is active contains a consistent database snapshot and an explicit policy for in-flight jobs.
- [ ] Restore into an empty workspace preserves IDs, relationships, source hashes, history, and playlists.
- [ ] Missing/corrupt manifest files are reported before the restore is activated.
- [ ] Untrusted archive paths, symlinks, and oversized members cannot escape the destination.
- [ ] The process is resumable or safely restartable and never deletes originals to make room.
- [ ] A documented recovery drill opens restored clips and exports a verified audio-preserving trim.

## Risks and evidence boundaries

- Derived caches can be regenerated, but original film and reviewed decisions must be included or explicitly identified as missing.
- File-by-file copying of an actively written database is not a sufficient consistency strategy.
