# EFA-001 — Establish the local application and capability boundary

**Status:** implemented
**Milestone:** M1 — Working local film library and safe external adapter foundations
**Priority:** P0
**Area:** foundation
**GitHub issue:** [#1](https://github.com/mfreeze77/exais-football-ai/issues/1)

## Outcome and user value

Start a private film room on one computer with actionable setup feedback and no automatic external processing.

## Scope

- Create the Python package, CLI, same-origin static application, and FastAPI startup/shutdown lifecycle.
- Load app-owned workspace configuration and expose health/capability information for FFmpeg, ffprobe, Kinovea, and optional football-cv.

## Non-goals

- Public hosting, account management, provider uploads, automatic weight downloads, or native desktop installers.

## Acceptance checks

- [x] A fresh configured data directory starts through the documented CLI and responds on loopback.
- [x] GET /api/health reports the application version and an explicit available/reason state for each optional capability.
- [x] Starting the app performs no film upload, model execution, or model download.
- [x] Startup and shutdown create/close the database and export worker without leaving duplicate workers.

## Dependencies

- None.

## Risks and evidence boundaries

- An optional missing executable must disable its dependent feature without hiding the rest of the library.
- Do not confuse an importable Python dependency with a qualified native application or trained model.
