# EFA-044 — Harden database migration and interrupted-write recovery

**Status:** planned
**Milestone:** M4 — Desktop convenience, recovery, scale, and release confidence
**Priority:** P1
**Area:** recovery
**GitHub issue:** [#44](https://github.com/mfreeze77/exais-football-ai/issues/44)

## Outcome and user value

Upgrade the application or recover from disk problems without losing a usable library.

## Scope

- Introduce versioned, reversible-where-feasible migrations and backup-before-upgrade checks.
- Handle disk-full, database lock, interrupted copy, and interrupted publication paths with explicit recovery state.

## Non-goals

- Silently repairing unknown corruption, downgrading incompatible schemas, or deleting film to free space.

## Acceptance checks

- [ ] Migrating a prior-version fixture preserves clip IDs, source hashes, revisions, and relationships.
- [ ] An interrupted migration rolls back or leaves a documented recoverable backup; partial schema is not opened as healthy.
- [ ] A newer unsupported database version is rejected with recovery guidance.
- [ ] Injected disk-full and permission failures do not mark media/artifacts complete.
- [ ] Startup identifies missing sources/orphan partial outputs without treating them as normal clips.
- [ ] Recovery procedures are demonstrated on copied fixtures rather than the only copy of user film.
