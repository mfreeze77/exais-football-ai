# EFA-035 — Correct suggested positions through a human review ledger

**Status:** planned
**Milestone:** M3 — Qualified optional football computer vision
**Priority:** P1
**Area:** review
**GitHub issue:** [#35](https://github.com/mfreeze77/exais-football-ai/issues/35)

## Outcome and user value

Fix an incorrect linebacker or quarterback suggestion without erasing what the model originally said.

## Scope

- Provide per-track position correction, rejection/suppression, rationale, and revision history.
- Keep provider output immutable and expose effective reviewed labels as a separate projection.

## Non-goals

- Training a model automatically, changing the source suggestion payload, or equating accepted position with named roster identity.

## Acceptance checks

- [ ] Changing a track's position records old suggestion, chosen label, source/run/track IDs, and review time.
- [ ] Rejecting a suggestion leaves its original payload available for comparison.
- [ ] Only supported position tokens or an explicit unknown/suppressed state can become effective labels.
- [ ] An older run's correction is not applied to a new run merely because a numeric track ID repeats.
- [ ] Exports and overlays state whether their labels are unreviewed suggestions or human-reviewed values.

- A correction UI must preserve uncertainty rather than requiring a guessed position.
